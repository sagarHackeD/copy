44. ACID Properties of Database Transactions
Transactions are designed to guarantee data integrity in concurrent and failure-prone environments. The four key properties are:
# Atomicity
All operations in a transaction are treated as a single unit. Either all are performed, or none are. If any part fails, the entire transaction is rolled back. Implemented using undo logging and rollback mechanisms.
# Consistency
A transaction moves the database from one consistent state to another. All defined integrity constraints (keys, referential integrity, check) hold before and after the transaction. If a transaction would violate a constraint, it is aborted, preserving consistency.
# Isolation
Concurrently executing transactions do not interfere with each other. Each transaction appears to run in isolation, as if it were the only one in the system. This is enforced by concurrency control (e.g., two-phase locking, snapshot isolation). The degree of isolation can be adjusted (e.g., Read Committed, Serializable).
# Durability
Once a transaction commits, its changes persist even in the event of a system crash or power failure. Achieved via redo logging and writing commit records to stable storage before acknowledging commit success. Recovery mechanisms use the log to re-apply committed transactions.
