41. ARM Processor Exceptions and Modes
An exception is any event that disrupts the normal sequential execution of instructions to require immediate attention from the processor. This includes resets, instruction fetch or data access failures, undefined instructions, software interrupts, and external hardware interrupts.
ARM Processor Modes and Associated Exceptions
| Exception | Mode | Main Purpose | Mode Bits (M[4:0]) |
| Reset | Supervisor (SVC) | Processor initialization and OS booting. Highest priority. | `10011` |
| Fast Interrupt Request | FIQ | For fast, low-latency interrupt handling. | `10001` |
| Interrupt Request | IRQ | For general-purpose interrupt handling. | `10010` |
| Prefetch/Data Abort | Abort | Memory access violations, virtual memory management. | `10111` |
| Undefined Instruction | Undefined | Software emulation of hardware or coprocessor instructions. | `11011` |
| Software Interrupt (SWI) | Supervisor (SVC) | System call to the Operating System. | `10011` |

When an exception occurs, the ARM core automatically performs a mode switch to handle it. The processor enters a specific mode, which has its own banked (dedicated) registers to protect the state of the previous mode.

The Vector Table is a table of addresses that the ARM core uses to find the appropriate exception handler. It's typically located at the start of memory (e.g., address `0x00000000`). The table contains either a branch instruction (`B <address>`) or a load instruction (`LDR pc, [pc, #offset]`) to jump to the handler's code.
