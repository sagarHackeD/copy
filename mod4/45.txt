45. Stored Procedure in SQL with Example
A stored procedure is a pre-compiled collection of SQL statements and control-of-flow logic stored on the database server. It can be invoked by applications to perform a well-defined task, often accepting parameters and returning results.
# Advantages
- Reduced network traffic: Instead of sending many individual statements, the application calls one procedure.
- Modular programming: Reusable and maintainable code.
- Enhanced security: Users can be granted permission to execute a procedure without direct access to the underlying tables.
- Improved performance: The procedure is parsed and optimized once, then cached; execution plans are reused.
- Business logic enforcement: Complex rules reside in the database, ensuring consistency.
# Example: Transfer Funds Procedure
We want a procedure `transfer_funds` that moves money between two accounts while logging the transaction.
```sql
CREATE PROCEDURE transfer_funds(
    IN from_acc INT,
    IN to_acc   INT,
    IN amount   DECIMAL(10,2),
    OUT msg     VARCHAR(100)
)
BEGIN
    DECLARE from_balance DECIMAL(10,2);
    DECLARE exit HANDLER FOR SQLEXCEPTION
    BEGIN
        ROLLBACK;
        SET msg = 'Transaction failed, rolled back.';
    END;
    START TRANSACTION;
    
    SELECT balance INTO from_balance FROM Accounts WHERE acc_id = from_acc FOR UPDATE;
    
    IF from_balance IS NULL THEN
        SET msg = 'Source account does not exist.';
        ROLLBACK;
    ELSEIF from_balance < amount THEN
        SET msg = 'Insufficient funds.';
        ROLLBACK;
    ELSE
        UPDATE Accounts SET balance = balance - amount WHERE acc_id = from_acc;
        UPDATE Accounts SET balance = balance + amount WHERE acc_id = to_acc;
        INSERT INTO Transfers(from_acc, to_acc, amount, transfer_time) 
             VALUES(from_acc, to_acc, amount, NOW());
        COMMIT;
        SET msg = 'Transfer successful.';
    END IF;
END;
```
Calling the procedure:
```sql
CALL transfer_funds(101, 202, 200.00, @status);
SELECT @status;  -- shows the outcome message
```
The procedure enforces the whole transfer as an atomic unit, uses exception handling to roll back on errors, and abstracts the multi-step logic into a single call.
