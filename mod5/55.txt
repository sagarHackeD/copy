55. NoSQL Graph Database - Neo4j
A graph database uses graph structures for semantic queries, with nodes representing entities, edges (relationships) representing relationships, and properties storing information about both.
Neo4j is the most prominent native graph database. It stores data in nodes and relationships, and offers the declarative query language Cypher (similar to SQL but for graphs).
# Core Concepts
- Node: An entity (e.g., Person, Movie). Each node can have labels (like types) and properties (key-value pairs).
- Relationship: Connects two nodes with a direction, a type, and properties. e.g., `(Person)-[:ACTED_IN {role: "Neo"}]->(Movie)`.
- Path: A sequence of nodes and relationships.
# Examples with Cypher
Create nodes and relationships:
```cypher
CREATE (m:Person {name: "Morpheus", age: 45})
CREATE (n:Person {name: "Neo", age: 30})
CREATE (m)-[:KNOWS {since: 1999}]->(n)
```
Query:
- Find all persons who know someone:  
  ```cypher
  MATCH (p:Person)-[:KNOWS]->(friend)
  RETURN p.name, friend.name
  ```
- Find the movie "The Matrix" and all actors:  
  ```cypher
  MATCH (m:Movie {title: "The Matrix"})<-[:ACTED_IN]-(actor)
  RETURN actor.name
  ```
- Shortest path between two nodes:  
  ```cypher
  MATCH path = shortestPath((a:Person {name:"Neo"})-[*]-(b:Person {name:"Morpheus"}))
  RETURN path
  ```
# Advantages of Neo4j
- Native graph storage and processing, giving high performance for traversals and connected data queries.
- ACID transactions.
- Highly expressive Cypher language for pattern matching.
- Suitable for social networks, recommendation engines, fraud detection, knowledge graphs.
