31. How Registers are Allocated to Optimize a Program
Register allocation is the process by which a compiler maps the infinite virtual variables in your source code to the finite physical registers of the CPU (ARM has 16 general-purpose registers). This is the most critical optimization because accessing registers is ~100x faster than accessing RAM.
Key Allocation Techniques:
1.  Live Range Analysis: The compiler builds a control-flow graph and determines the "lifespan" of each variable (from its first definition to its last use). Variables whose live ranges do not overlap can share the same physical register.
2.  Graph Coloring (Chaitin's Algorithm): Variables are treated as nodes in a graph. Edges connect variables that overlap in time. The compiler tries to assign colors (physical registers) to nodes so that no two connected nodes share a color. If a color isn't available, the variable is spilled to the stack.
3.  Register Spilling: When there are more active variables than registers (e.g., R0-R12 are general-purpose), the compiler saves some variables to memory (stack frame) and reloads them later. Spilling is slow, so optimizers try to avoid it inside tight loops.
4.  ARM Calling Convention (AAPCS) Allocation Rules:
- R0-R3: Scratch / Argument registers. Pass first 4 arguments to functions. Caller-saved (must be saved by caller if needed after a `BL`).
- R4-R11: Callee-saved. Used for local variables. A function must preserve them (push/pop).
- R12 (IP): Intra-procedure scratch.
- R13 (SP): Stack Pointer.
- R14 (LR): Link Register.
- R15 (PC): Program Counter.
The compiler prioritizes using R0-R3 first, then R4-R11, to minimize stack usage.
