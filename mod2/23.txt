23. Integrity Constraints and the Importance of Referential Integrity
Integrity Constraint  
A rule that restricts the data that can be stored in a database to ensure accuracy, consistency, and reliability. Constraints are part of the database schema and are enforced by the DBMS.
Referential Integrity Constraint  
This constraint involves two relations and specifies that a value appearing in a foreign key column of a referencing relation must either be NULL (if permitted) or match the primary key value of a tuple in the referenced relation.
Formally: If relation R1 has a foreign key FK that references relation R2's primary key PK, then for every tuple in R1, FK = PK in some tuple of R2, or FK is NULL (if allowed).
#Importance of Referential Integrity
- Maintains consistency across relations: Prevents orphan records (dangling references) where a foreign key points to a non-existent record.
- Ensures valid relationships: For instance, an employee's department number must correspond to a real department; an order must be linked to an existing customer.
- Supports data quality: Without it, applications could easily insert meaningless or corrupt data.
- Facilitates cascading actions: The DBMS can automatically cascade updates/deletes to preserve consistency, reducing application logic.
- Foundation for relational model: Referential integrity is one of the core pillars that distinguish a relational DBMS from simple file storage.
